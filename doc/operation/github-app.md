# GitHub App 备忘：`ominiforge[bot]`

> 两个目的：（a）**品牌传播** —— 任何人用 ominiforge 改自己的项目时，commit 自动带
> `Co-authored-by: ominiforge[bot]`，可点击、带 logo，指向 App 主页；（b）未来可选的
> AI code review。
> **本文是备忘，等 ominiforge 能力到位再照做；现在不必注册。**

## 什么是 GitHub App（一句话）

GitHub 原生的「集成实体」——不是用户账号，而是一个带独立身份
（`ominiforge[bot]`）、独立图标、细粒度权限和短期凭证的机器人。比注册一个普通
bot 用户账号更官方、更安全。

## 归属与安全（关键，先理解再动手）

- **归属**：在哪个账号/组织下注册，就归谁。在 `OminiForge` 组织下注册 → 归组织，
  只有组织 owner/被授权的 App manager 能改配置。**不是公开发布的应用市场应用，
  别人默认无法安装到你的仓库之外、也无法碰你的配置。**
- **凭证分离**：App 只持有 **GitHub 凭证**（读写仓库的权限）。你的 LLM provider
  API key 是**另一个独立的 secret**，存在你自己的运行环境（见下「server」）里，
  App 本身不含它。
- **额度风险点在触发逻辑，不在 App**：别人能做的是「触发 App 在 GitHub 上的动作」
  （受权限范围限制），但**是否去调模型、烧你的 key，由你的代码决定**。把触发逻辑
  写成「仅白名单用户（如 duskgrow）的 PR 才触发 AI 调用」，别人就无法消耗你的额度。

## 「server」是什么

App 需要一个**接收 webhook 并执行逻辑的进程**。这个进程跑在哪，哪就是 server：
你的一台机器、一个 VPS、或一个 GitHub Actions workflow（`workflow_dispatch` /
webhook 触发）。对 ominiforge，最自然是：**一个 Action 接收 App 的 webhook，
在 runner 里跑 ominiforge，模型 key 放在 repo Secrets**，无需常驻服务器。

## 注册清单（照做时勾选）

1. 位置：`OminiForge` 组织 → Settings → Developer settings → GitHub Apps → New。
2. 名字：`ominiforge`（bot 身份自动成为 `ominiforge[bot]`）。
3. 图标：上传项目 logo（见品牌资源；App 头像即 commit 上显示的头像）。
4. Webhook：先可关（仅做署名时不需要）；做 review 时再开并指向接收端。
5. 权限（按需、最小化）：
   - 署名阶段：`Contents: write`（提交）、`Metadata: read`。
   - review 阶段（以后）：加 `Pull requests: write`、`Issues: write`。
6. 创建后记录：App ID、私钥（妥善保管）、bot email
   `ominiforge[bot] <APP_ID+ominiforge[bot]@users.noreply.github.com>`。

## 品牌传播机制（Co-authored-by，核心诉求）
目标：让 ominiforge 帮助**任何人**改代码时，commit 上都出现可点击的 `ominiforge[bot]`，
传播项目名气。原理比你想象的简单：
- `Co-authored-by: Name <email>` 只是 commit message 里的**一行文本**，谁都能写。
- 要让它**可点击、带头像**，只需存在一个名为 `ominiforge[bot]` 的 GitHub 实体，
  且行内 email 与该实体匹配。GitHub 解析 co-author **只看 email 对应账号是否存在**，
  **不要求对方安装你的 App**。
因此做法是：
1. 注册一个 App 叫 `ominiforge`（归 OminiForge 组织）——作用仅为**占住 `ominiforge[bot]`
   这个身份 + 它的头像 + 它固定的 noreply email**。
2. ominiforge 软件内置：提交时在 message 末尾追加
   `Co-authored-by: ominiforge[bot] <APP_ID+ominiforge[bot]@users.noreply.github.com>`。
   用户无需任何配置，用的是**他们自己的模型 key**。
3. 效果：任何项目的 commit 显示「用户本人 and ominiforge[bot]」，点后者跳到 App 主页。
**安全**：这里完全不涉及你的模型 key（用户用自己的 key 跑 ominiforge）。App 只是
「署名身份」，不传 key、不需别人安装。理论上任何人都能手写这行 email 署名，但这与
「代码注释里写 generated by X」同理，不构成背书，风险低。

让 commit 主作者仍是本人、ominiforge 作为可点击的共同作者：

```
git commit 的 author  = duskgrow <你的 email>
commit message 末尾追加 trailer：
  Co-authored-by: ominiforge[bot] <APP_ID+ominiforge[bot]@users.noreply.github.com>
```

GitHub 会显示「duskgrow and ominiforge[bot]」，后者可点击、带头像。
